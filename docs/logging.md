# 日志器

应用通过 `alira.common.utils.logger.logger` 输出彩色控制台日志，同时按日志器名称将纯文本保存到 `SERVER.base_dir/<name>/YYYY-MM-DD[_index].log`。Apixis 自身的日志仍由依赖管理。

服务加载路由后，由 `AutoInit` 依次启动日志器、Apixis 核心和其他已注册服务；日志器启动前的日志先进入缓冲区。关闭时按注册逆序清理其他服务和核心，最后排空日志并等待写入线程退出。直接使用 SDK 时，调用 `await logger.start()`，退出时调用 `await logger.stop()`。需要提前读取文件时调用 `await logger.flush()`。

## 写入与错误处理

- 一个独立线程处理普通日志的批量写入和文件轮转，文件不跨批次保持打开。生产者只负责格式化、加入缓冲区和同步输出控制台。
- `LOG.log_buffer_size` 控制待写记录数量，默认 100。满批立即写入，低流量时约每 200 ms 刷新；磁盘繁忙时实际完成时间会延长。
- 运行期间缓冲区满时，调用线程等待写入线程取走一批，不丢弃已接收记录。这种背压也可能阻塞调用日志器的事件循环，尤其是在慢磁盘或持续过载时。
- 启动前保留最近一个缓冲区的记录；超出的记录会被淘汰，并在写入线程启动时向 stderr 报告数量。关闭开始后新调用只输出控制台；关闭完成后的调用重新进入启动前缓冲区。进程正常退出时会尝试排空残留记录。
- `flush()` 等待调用前已接收的记录完成写入，`stop()` 还会等待线程退出。取消等待者不会中断已经运行的文件操作；后续启动会等待上一次关闭完成。
- 文件失败立即向 stderr 报告，并由下一次 `flush()` 或 `stop()` 抛出 `RuntimeError`。失败批次不自动重试，避免部分写入后重试产生重复；其他日志器名称的文件仍会尝试写入。
- 轮转按 UTF-8 字节数和记录边界执行，单条记录大于 `LOG.max_log_file_size` 时独占一个超限文件。支持跨日切换和已有文件续写。
- 写入成功表示数据已交给操作系统，不包含 `fsync`。轮转协调范围为当前进程。

`exception()` 会附加当前异常堆栈；`separator()` 使用 INFO 级别。显式导出接口 `await logger.write_log(folder, filename, message)` 使用线程池完成一次追加：字典写入 `.jsonl`，其他内容以原始文本写入 `.log`，路径限制在存储根目录内。这个接口独立于普通日志的批处理和轮转。

时间字符串按秒缓存；调用者定位跳过日志器自身栈帧后再访问局部变量，避免每条记录重复格式化时间和检查内部方法的局部变量。

## 性能验证

运行：

```sh
.venv/bin/python benchmarks/logger.py --records 20000 --rounds 6
```

脚本使用临时目录和相同的文件输出实现，单条消息为含中文的约 180 字节文本，每批 100 条；正反交替运行各方案，预热并在每轮前收集垃圾。每个文件写入方案验证完整输出，统计包含最终排空的耗时；每轮总耗时除以记录数，再取六轮中位数。线程启动在计时外，关闭和排空在计时内。控制台和消息格式化单独测量，所有文件方案均不执行 `fsync`。

本机 Python 3.12.12、macOS ARM64 的一次六轮结果如下。数值为每条记录的微秒数，代表本机文件系统与页缓存条件，不代表物理磁盘持久化速度。

| 方案 | 调用方中位耗时 | 全部写完中位耗时 | 全部写完范围 |
| --- | ---: | ---: | ---: |
| 同步逐条打开、追加、关闭 | 34.823 | 34.823 | 34.500–35.364 |
| 同步批量写入 | 0.829 | 0.829 | 0.764–1.024 |
| 每批 `asyncio.to_thread` 写入 | 1.175 | 1.175 | 1.092–1.393 |
| 独立线程批量写入 | 1.125 | 1.136 | 1.050–1.149 |
| 独立线程传递和批处理调度，文件输出为空操作 | 0.314 | 0.318 | 0.308–0.335 |

独立线程比同步批量写入多约 0.31 µs/条，不能据此声称线程提高了总吞吐量。相对线程池批量方案，本次中位耗时仅减少约 3%，范围重叠，差异不足以视为稳定收益。主要吞吐收益来自批处理；独立线程让业务线程避开文件操作，并统一写入顺序和轮转状态。队列持续饱和时，背压仍会让业务线程承担文件吞吐上限。

同次测量中，格式化加输出到内存流约为 1.92 µs/条，未包含入队成本；真实终端或重定向管道可能更慢。低流量记录还有最长约一个刷新周期的等待，不能用上表的批量吞吐时间代表单条日志落盘延迟。
